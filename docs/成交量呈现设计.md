# 成交量呈现设计（分时/日K量柱副图 + 量比）

> 2026-11-02 实现。目标：通过「量价对照」观察主力行为——单看当日成交量的绝对数
> （如「12.3万手」）没有参照系，必须给量配上对比基准。本文档记录数据链路、口径、
> 呈现规则与降级行为；字段契约的唯一维护处仍是 `core/data_define/`。

## 一、呈现设计：三层对比，各答一个问题

| 层 | 呈现位置 | 对比基准 | 回答的问题 |
|---|---|---|---|
| 分钟级 | 分时图下段量柱 | 同日其他分钟 | 主力日内动作：开盘放量、脉冲拉升、尾盘砸盘 |
| 日级 | 日K图下段量柱 + 黄色5日均量线 | 近几日 | 温和堆量（吸筹）、天量（见顶）、量价背离（虚涨） |
| 数字级 | 底部「成交量」格小字量比 | 近5日同时刻 | 一个数字回答「今天有没有异动」 |

三条经验刻度：量比 ≥1.5 温和放量（橙色）、≥2.5 明显放量（红色）、≥5 剧烈异动。

**为什么是副图量柱而不是折线叠加**：量价对照要求 x 轴严格对齐（某根量柱正上方就是
同一分钟的价格点/同一天的蜡烛）；两条不同量纲的折线叠在同一块小画布上互相穿插，无法
阅读。副图量柱也是行情终端的通用语言，无学习成本。

## 二、数据链路（按架构分层）

```
腾讯接口 ──> core/stock_api.py ──> core/data_define 契约 ──> core/history 入库
                                        │
                                        └──> core/data_source.py ──> 组件 API ──> ui.html 绘制
离线回放：market_point(payload) ──> store.minute_day_totals ──> core/vol_calc.volume_ratio
```

- **契约**（`core/data_define/`）：
  - `KlineBar.vol`：日K成交量（手）。腾讯 fqkline/备用端点每行第 6 列。
  - `RealtimeQuote.liang_ratio`：量比。腾讯批量行情 f[49]（实测确认，f[38] 为换手率备用）。
  - `MinutePoint.vol`：原有字段（截至该时点累计成交量，手），本次未改动。
- **取数**（`core/stock_api.py`）：日K第 6 列经 `_opt_float`（已增强：非字符串元素安全）；
  量比经 `_opt_float(f, 49)`，美股该位置非数值时自然为 None。
- **持久化**（`core/history/`）：行情行存契约 payload JSON，**无 schema 迁移**；新字段
  自 2026-11-02 采集起自然入库。`store.minute_day_totals(code, before, days)` 为量比
  兜底新增的只读查询（SQL 按 `trade_date` 分组取 `MAX(json_extract(payload,'$.vol'))`，
  同日多版本取最大累计值，命中 `point_history` 索引）。
- **纯函数**（`core/vol_calc.py`，仿 group_calc 先例，合成数据可测）：
  - `minute_deltas(points)`：累计量 → 单分钟量。任一点无量返回 None；负差分累计超过
    末端累计量 1% 判数据损坏返回 None（整段不画），小幅毛刺钳 0。
  - `volume_ratio(today_points, past_day_totals)`：量比折算（离线兜底用）。
    当日按已有点数折算分钟均量，历史按 240 分钟/日折算，相除。
    **量纲护栏**：结果落在 [0.02, 100] 之外视为旧快照误存成交额（元）与手混排
    （实测瑞芯微混排折算 ≈3e-5），返回 None 显示 --，宁缺毋错。
- **数据源**（`core/data_source.py`）：在线路径零改动（payload 多字段自动流过）；
  离线回放 `_replay_quote_from_history` 增加 liang_ratio 折算兜底。
- **组件**（`components/stock/`）：**不新增 API 方法**——量随既有 `get_realtime` /
  `get_minute_data` / `get_kline` 载荷到达。画布 92→122px，组件 embed_height 400→440。

## 三、绘制规则（components/stock/ui.html）

- 画布上下分区：上段价格（原逻辑压缩至约 70% 高），下段量柱（约 30%，最少 24px），
  细分隔线隔开，x 轴严格对齐；无量数据时价格占满全高（原行为）。
- **分时量柱**：`volDeltas()`（与 vol_calc 同口径的 JS 版）差分累计量；第 i 根柱颜色
  = 第 i 分钟价 vs 前一分钟价（首分钟 vs 昨收），红涨绿跌，透明度 0.8。
- **日K量柱**：颜色 = 当日蜡烛阴阳；叠加黄色 5 日均量虚线（窗口内任一日无量则该点
  断开，复用 shared.js `strokeSeries` 的 null 断点能力）；左上角图例「量柱 · 5日均量」。
- **量比小字**：成交量格下方，`量比 x.xx`；≥2.5 红、≥1.5 橙、其余灰。空值显示空白。

## 四、降级与数据质量边界（与《数据库设计》第 5 节一致）

| 场景 | 行为 |
|---|---|
| 旧库日K行无量（2026-11-02 前） | 该日无柱，5日均量线在该处断开；整窗全无量则不画副图 |
| 旧快照分时 vol 误存成交额 | 单日内自洽仍画柱（形态可用）；参与量比折算时被 [0.02,100] 护栏拦截显示 -- |
| 分时累计值大幅回退（>末端1%） | 数据损坏，量柱整段不画，价格占满 |
| 美股行情无量比字段 | liang_ratio 为 None，小字空白 |
| 离线回放且库内无近5日分时 | 量比折算输入不足，显示 -- |

**历史不回填**：不重新抓取历史日K覆写旧行（会拼接不同前复权版本，违反历史库不可变
原则），量柱自上线之日起自然积累。

## 五、测试

- `tests/test_data_define.py`：liang_ratio / vol 契约往返、旧行容错（vol → None）。
- `tests/test_vol_calc.py`（新）：差分正常/毛刺钳0/损坏判None/缺量；量比全天、盘中、
  输入不足、量纲混排拦截。全部合成数据，无网络。
- `tests/test_history_store.py`：`minute_day_totals` 近N日、同日多版本取最大、给定日
  不计入、无数据返回空（夹具日K行补 vol 对齐契约归一化）。

## 六、后续候选（本次未做）

- 分时**均价线（黄线）**：`Σ price×Δvol / Σ Δvol` 近似 VWAP，与量柱配合才是完整的
  分时主力观察工具。
- 底部格子**换手率**（行情 f[38] 现成）替换低频格（如 PE静）。
- 量比历史曲线（需要分时历史更长覆盖）。
