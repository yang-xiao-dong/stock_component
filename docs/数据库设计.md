# 行情数据库设计与维护约定

本文面向后续开发者和智能体，说明已实现的结构、数据口径、迁移与验证流程。用户操作见《使用说明》。

## 1. 模块边界

```text
config.py                         当前配置唯一入口
core/data_define/history.py       MarketBatch / ClosePoint / ReplayContext / HistoryStatus / DataModePreference 契约
core/data_define/fundamental.py   FundamentalRecord 契约（外部核验基本面，暂无生产消费端）
core/stock_api.py                 腾讯适配器：请求、解析、实际复权口径、原始响应片段
core/history/settings.py          汇总组件的股票与窗口需求，生成历史配置副本
core/history/service.py           统一采集、缓存、冻结回放版本；不写 SQL
core/history/store.py             唯一数据库仓储：事务、查询、内容去重、备份/导出
core/history/schema.py            有序数据库迁移；无网络依赖
core/history/legacy.py            旧 JSON 快照导入；不修改原文件
core/history/__main__.py          独立维护命令；不联网、不启动窗口
core/data_source.py               组件唯一公共入口、模式管理、收盘调度
components/*                     只取数据、计算与展示；禁止直接依赖数据库或 stock_api
```

行情数据流为：供应商 → 契约与校验 → 事务入库 → 仓储读回 → 计算与组件。在线显示与离线回放都读取持久化版本。写入失败不会把未落盘数据当作已保存的数据返回。

首版采用 SQLite（Python 标准库），无额外数据库服务。源码数据库为 `data/market.sqlite3`，EXE 数据库为 `%LOCALAPPDATA%/StockWidget/data/market.sqlite3`。路径只能经 `core.runtime_paths.user_data_path` 构造，不能写到 EXE 解包目录。

## 2. 为什么采用“数据点 + 序列版本 + 回放引用”

一条价格事实归属一个股票、数据域、交易日和时点。同一批数据包含若干价格事实；一次回放引用各数据域的具体批次。

`market_point` 逐点保存契约 JSON，`dataset` 保存口径和原始响应片段，`dataset_point` 保存序列成员与顺序。JSON 内的行情字段只在 `data_define` 定义，仓储不复制一份行情字段清单，也不把整个交易日快照作为唯一查询单位。股票、日期、数据域和时点有独立索引列，可先过滤再解析字段。

采用这种结构是为了同时满足：字段契约单一维护、修订前后可追溯、不同复权口径不拼接、相同数据点复用以及跨数据库导出。代价是价格聚合需要通过仓储解码 JSON；未来大量 SQL 分析可以新增派生列/物化表，但不可丢弃原始版本或改变内容 ID 算法。

内容 ID 是规范 JSON（UTF-8、键排序、紧凑分隔符、拒绝 NaN/Infinity）的 SHA-256。数据点内容未变则复用；序列口径、原始响应或请求长度变化会生成新的序列版本。`dataset.raw` 保留供应商本股票响应片段（行情原始字段字符串、图表原始行或分时对象），不包含 HTTP 全报文、鉴权头或其他股票的响应。

## 3. 表结构（schema version 1；v2 追加见文末 fundamental 表）

以下 `TEXT` 时间和日期均采用可排序的 ISO 格式；`INTEGER` 为整数。内容字段存普通 JSON 文本，避免依赖 SQLite 专属 JSON 查询函数。

### schema_migration：数据库结构版本

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| version | INTEGER PK | 已成功执行的迁移版本 |

### instrument：股票稳定身份

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| code | TEXT PK | 应用统一代码，如 sh603893、usQCOM |
| market | TEXT NOT NULL | CN / HK / US |
| currency | TEXT NOT NULL | CNY / HKD / USD |
| timezone | TEXT NOT NULL | 市场时区，如 Asia/Shanghai、America/New_York |

名称在行情观测中保留，避免用现在的名称覆写历史名称。供应商原始代码保留在原始响应中；应用身份与供应商别名不可混为一谈。首版通过代码前缀识别市场，新增市场应扩展识别规则并补测试。

### profile：计算配置版本

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | TEXT PK | 配置内容 SHA-256 |
| payload | TEXT NOT NULL | 配置 JSON |

保存 STOCKS、GROUP_NAME、PRINCIPAL、WEIGHT_MODE、KLINE_DAYS、ANALYSIS、PE_COMPARE，以及 CALCULATION_VERSION。历史回放优先使用保存的配置。旧快照没有记录配置时使用当前配置，并明确提示无法完整复现当时参数。

CALCULATION_VERSION 首版为 1。改变计算口径时必须提高版本并设计兼容策略；单纯保存版本号不会自动运行历史算法，当前实现仅包含当前算法。

### dataset：不可变数据序列版本

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | TEXT PK | 股票、域、来源、复权口径、规范行、原始片段、请求长度的内容哈希 |
| code | TEXT NOT NULL，FK instrument.code | 股票 |
| kind | TEXT NOT NULL，CHECK | quote / minute / kline / close |
| source | TEXT NOT NULL | tencent / legacy_snapshot |
| adjustment | TEXT NOT NULL | none / qfq / unknown |
| start_date / end_date | TEXT NOT NULL | 序列首末交易日 |
| row_count | INTEGER NOT NULL | 有效数据点数量 |
| requested_count | INTEGER，可空 | 请求的日K/收盘价窗口长度 |
| raw | TEXT，可空 | 原始片段 JSON；不是交易结果或 UI 内容 |
| contract_version | INTEGER NOT NULL | 解析契约版本，首版为 1 |

索引 `dataset_stream_date(code, kind, end_date)`。日K和PE收盘价使用不同 kind：即使数值相同也不能以日K替代未保存的PE收盘序列。

### market_point：跨序列复用的行情数据点

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | TEXT PK | 股票、域及规范行情行的内容哈希 |
| code | TEXT NOT NULL，FK instrument.code | 股票 |
| kind | TEXT NOT NULL | 数据域，与 dataset.kind 对应 |
| trade_date | TEXT NOT NULL | 供应商数据的交易日 YYYY-MM-DD |
| event_time | TEXT NOT NULL | 行情：原始 yyyyMMddHHmmss；分时：HH:mm；日K/收盘价：空字符串 |
| payload | TEXT NOT NULL | 对应 RealtimeQuote / MinutePoint / KlineBar / ClosePoint 的完整 to_dict() |

索引 `point_history(code, kind, trade_date, event_time)`。同一股票同一时刻可能有多个内容版本，不能对上述四列强加唯一约束而覆盖修订值。数值必须有限，必要价格字段大于零，日K高低价关系正确，序列中同一时点不允许重复。

### dataset_point：序列成员

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| dataset_id | TEXT NOT NULL，FK dataset.id | 序列版本 |
| ordinal | INTEGER NOT NULL | 按交易日/时点排序后的零基序号 |
| point_id | TEXT NOT NULL，FK market_point.id | 数据点 |

联合主键 `(dataset_id, ordinal)`。序列必须通过此表恢复，禁止把若干 qfq 序列各取一段拼接，以免混合不同除权基准。

### ingestion：采集审计与失败记录

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | INTEGER PK | 本库内递增采集编号；导出时保留 |
| code / kind | TEXT NOT NULL | 请求目标 |
| received_at | TEXT NOT NULL | 接收/保存时间，UTC ISO，含微秒和 +00:00 |
| dataset_id | TEXT，可空，FK dataset.id | 成功采集引用的内容版本；失败为 NULL |
| profile_id | TEXT NOT NULL，FK profile.id | 当次配置 |
| error | TEXT，可空 | 失败原因 |

索引 `ingestion_stream(code, kind, id)`。即使返回内容未变化也保留成功采集记录，行情事实仍复用。失败不删除或改写既有数据版本。业务交易时间和接收时间分别保存，不用电脑当前日期替代供应商交易日。

### replay：历史回放版本

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | TEXT PK | 日期、引用、配置、缺失清单、来源的内容哈希 |
| trade_date | TEXT NOT NULL | 回放基准日期 |
| saved_at | TEXT NOT NULL | 保存时间（UTC ISO） |
| profile_id | TEXT NOT NULL，FK profile.id | 回放计算配置 |
| missing | TEXT NOT NULL | 数据不足清单 JSON 数组 |
| origin | TEXT NOT NULL | collected / legacy / reconstructed |

索引 `replay_date(trade_date, saved_at)`。重复保存完全相同的回放是幂等的；变化产生新版本。界面按日期选择时，优先最新无缺失回放，其次最新部分回放，避免临时采集失败使原本可用的历史回放退化。所有旧版本仍保留。首版界面不提供同一天多版本选择器。

### replay_dataset：回放的固定输入引用

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| replay_id | TEXT NOT NULL，FK replay.id | 回放版本 |
| stream | TEXT NOT NULL | kind:code，例如 kline:sh603893 |
| dataset_id | TEXT NOT NULL，FK dataset.id | 具体行情版本 |

联合主键 `(replay_id, stream)`。同一回放中的取数始终落到这些 ID，不追随最新行情变化。

### imported_file：旧快照导入登记

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| digest | TEXT PK | 原文件字节 SHA-256，用于重复导入判定 |
| path | TEXT NOT NULL | 导入来源路径，仅作审计 |
| imported_at | TEXT NOT NULL | 导入时间 UTC |
| replay_id | TEXT NOT NULL，FK replay.id | 对应回放 |

原文件不覆盖、不删除。中途失败后可重试，已写入的事实和版本按内容去重。逐股票错误记录为回放缺失项，坏文件记录日志，不阻止其他文件导入。

### fundamental：外部核验的基本面参考（schema version 2 追加）

| 字段 | 类型/约束 | 含义 |
|---|---|---|
| id | TEXT PK | 规范 JSON `["fundamental", payload]` 的 SHA-256（与库内其他内容哈希同法） |
| code | TEXT NOT NULL，FK instrument.code | 股票 |
| as_of | TEXT NOT NULL | 数据截面日 YYYY-MM-DD |
| report_period | TEXT，可空 | payload 内最新披露报告期的冗余列，便于过滤 |
| payload | TEXT NOT NULL | FundamentalRecord（core/data_define/fundamental.py）完整 to_dict() |

索引 `fundamental_stream(code, as_of)`。存放外部数据源核验后导入的慢变参考数据（公司档案、股本、报告期财务、扣非、Beta、口径警示）：腾讯免费接口不提供这些字段，故不走行情采集/回放机制，store.py 暂不感知本表，由维护脚本直插（写法与 tests/test_fundamentals.py 的 `insert()` 一致：先 `INSERT OR IGNORE` instrument，再按内容哈希主键 `INSERT OR IGNORE`）。

- 读取约定：每代码取 `as_of` 最大（并列取 id 降序）的一条；修订＝新 as_of 新行、旧行留痕；同内容重复导入因内容哈希幂等。表中现有两类行：**核验快照行**（as_of=核验日，字段最全）与**报告期历史行**（as_of=报告期末，仅报告期指标；`净利润同比`为含少数股东净利口径，与归母口径存在合理偏差）——最新读取自然落在快照行。
- 数据来源：种子文件 `docs/fundamentals_2026-10-23.json`（11 条核验快照，过程见《数据核验与补充_2026-10-23》）与 `docs/fundamentals_report_periods_2026-10-24.json`（342 行报告期历史，MCP 批量取数，已过隐含重构与快照双重校验）。
- 边界：`backup` 命令（在线备份 API）完整包含本表；`export`/`restore` JSONL 与 `info` 计数暂不包含（接入需扩展 store.TABLES 并同步导出/恢复测试）。schema 升至 2 后，restore 的版本校验为精确相等，不再接受 v1 头部的旧导出。

## 4. 在线和离线一致性

- 统一采集需求：组内股票行情、分时、`max(KLINE_DAYS, ANALYSIS.kline_days)` 日K；PE全部对比股与参照股行情及 `PE_COMPARE.kline_days` 收盘价。不同消费者只裁剪同一版本，不重新计算复权。
- 获取成功立即入库并读回，即使没有点击“保存当前”也保留。缓存共用 REFRESH 间隔；后台 history.collect 每 60 秒汇总需求并创建回放，“保存当前”强制刷新一轮。
- 当日手动保存与自动采集可以产生多个引用版本。所谓一致是“同一数据版本与参数得到相同数值”；在线行情随后更新，并不意味着其数值必须永远等于早先回放。
- 已有回放固定版本和配置。没有回放但有历史价格的日期，按日期从库中重建并标记 reconstructed；报价、分时必须属于该日，日K/收盘价裁剪到该日，绝不读未来交易日的行。
- 重建允许使用后来补采的历史价格，所以不等同于严格的“当时已知信息”回测；需要该语义应新增按 received_at 截止的查询，不能改写已有固定回放。
- 离线分支、离线手动保存、离线收盘任务都不启动网络请求。切换前已经发出的请求可完成落盘，但结果不得发布到新模式；未开始的后续采集跳过。
- 数据模式偏好原子保存为数据库同目录的 `history_mode.json`；启动时先恢复离线日期，再启动组件和后台调度，因此离线重启无需联网。此文件是用户偏好，不属于行情库导出；偏好文件缺失时默认在线。
- 模式切换代数用于失效全部组件缓存；同一天重选也失效。股票列表、本金、窗口和分析配置从回放 profile 读取。
- 组合建仓仍按“该次查询窗口首日开盘价”，不能用数据库最早数据日建仓。组合、PE和判断结果按纯函数重算。

## 5. 数据质量与边界

- 腾讯日K返回 qfqday 才标记 qfq；day 或备用端点标记 none。美股PE收盘价接口仅有 qfq，保留该口径。首版不提供自行复权算法或统一除权因子库。
- 实时报价以响应变量名匹配股票，不按返回位置匹配。规范 quote.code 始终使用应用代码，供应商裸代码/美股后缀保留在原始响应。美股的 ISO 日期时间统一为契约要求的市场本地 yyyyMMddHHmmss，原始字符串继续保留。
- 新分时 HHmm 统一为 HH:mm；腾讯分时第3项是该时点累计成交量（手），第4项是累计成交额，新采集的 vol 取第3项。需要单分钟成交量时应按相邻累计量相减并处理异常，不可直接求和。旧快照中的 vol 原样保留，因旧解析器可能存入成交额，旧值不可与新成交量直接比较。外部源救援导入的分时（如 Wind 分钟K，单位为股）在入库时折算为手，保证库内 minute.vol 口径唯一；折算入库以新序列版本表达，不改动旧版本。
- 旧 JSON 日K口径标为 unknown，缺失分时日期仅可用原快照日期补齐。旧快照没有独立 close 序列，禁止擅自用复权日K冒充PE收盘价。
- missing 包括请求失败、域缺失、窗口不足和交易日不匹配。complete 仅指所需流和窗口均取得，不代表逐分钟无缺口、正式收盘确认或交易所级完整性；上市时间不足也会产生窗口不足提示。
- A股组合以组内报价交易日为基准；分时和报价需对齐该日。美股参照保留自身交易日，在A股回放日以前可用，不将两个市场强行标成同一个交易日。
- 收盘任务按北京时间工作日 15:05 运行；首次启动已过时刻可补采，完成后安排下一个工作日，避免立即重新触发。交易所节假日尚未接入日历，返回数据按真实交易日归档，不凭工作日伪造交易日。
- 应用关闭期间不采集。无法从上游补回的历史分时、未采样的逐笔报价无法恢复；首版不安装系统后台服务。
- 行情价格及比例沿用现有 float 契约，此库是行情分析库，不是结算账本。需要财务级定点精度时新增契约版本和迁移。
- 每次采集原始片段及审计会增加库大小；数据点共享降低重复值占用，首版不自动删除历史。今后压缩/归档必须保持回放引用可恢复。

## 6. 事务、线程与备份

每次操作独立连接，不跨线程共享 sqlite3.Connection。启用 WAL、外键检查和 30 秒 busy timeout；进程内写操作串行，读取可以并行。一批有效数据、数据点引用、采集记录在同一事务提交。回放及其引用也是一个事务。

数据库运行时可能有 `-wal` / `-shm` 文件；不要仅拷贝运行中的 sqlite3 主文件作为备份。使用仓储 backup() / 下列 backup 命令，调用 SQLite 在线备份 API。导出 JSONL 在同一个读事务内完成，保证导出期间的数据一致性。维护操作输出必须使用新路径，不覆盖已有文件；中断输出可能是不完整文件，校验/恢复成功之前不能当作有效备份。

## 7. 维护与迁移命令

项目根目录执行；也可用 `.venv/Scripts/python.exe` 替代 python。`--db` 必须放在子命令之前。

```bash
python -m core.history info
python -m core.history backup data/market-backup.sqlite3
python -m core.history export data/market-export.jsonl
python -m core.history --db data/restored.sqlite3 restore data/market-export.jsonl
python -m core.history import-snapshots data/snapshots
python scripts/backfill_market.py --until 2015-01-01  # 回补日K/收盘价（腾讯直连、重叠窗口翻页、幂等）
python scripts/import_fundamentals.py                 # 基本面种子导入（幂等；--db 指定 EXE 库）
python scripts/import_rescue_minutes.py            # 救援分时JSON入库（docs/mcp 与 docs 下 minute_*.json，股→手折算，幂等；--db/--dry-run）
```

启动时自动扫描源码快照目录和 `%LOCALAPPDATA%/StockWidget/data/snapshots`，已导入内容跳过。整个旧快照目录可多次手动导入。

JSONL 第一行为格式、导出版本和 schema_version；之后每行是 `{table, row}`。导出顺序遵循外键依赖，保留主键和关系，没有 pickle、Python对象或绝对路径依赖（imported_file.path 仅审计）。restore 仅接受空库，版本/表名/字段/外键不匹配会整笔回滚。

迁移到 PostgreSQL 等服务端数据库时：实现相同仓储接口，创建等价外键/索引，按 JSONL 表顺序导入普通值，保留内容 ID；用在线/离线一致性测试验收。SQLite INTEGER PRIMARY KEY 的自增方式、INSERT OR IGNORE、连接与事务语法需要由新适配器替换，组件无需改 SQL。

## 8. 后续智能体修改流程

1. 先读本文、AGENTS.md、对应 data_define 契约及相关测试。
2. 改行情字段先改契约，再改供应商解析与消费者；旧字段缺失仍容错。改变规范化或哈希输入要显式提高契约版本并处理旧版本。
3. 结构变更只在 MIGRATIONS 末尾追加 `(version, statements)`，禁止修改已发布版本。已有迁移记录比程序新时拒绝写入，不自动降级。
